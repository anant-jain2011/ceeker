# ⚡ Ceeker (ckr)

### *The Philosophical, Lightning-Fast Package Manager & Build Tool for C/C++*

Ceeker is an ultra-modern, zero-config orchestration layer and build engine designed to liberate C/C++ developers from configuration hell. Heavily inspired by the ergonomics of **Bun** and **Cargo**, Ceeker auto-manages CMake pipelines, caches dependencies deterministically, and normalizes compilation down to single-command execution.

No boilerplate. No manual `CMakeLists.txt` editing. Just write code.

---

## 🏛️ The Ceeker Philosophy

1. **Zero Configuration by Default:** If your project follows logical conventions, it compiles seamlessly without questions.
2. **Deterministic Binary Caching:** Compile dependencies exactly once globally per target triple. Never wait for an unchanged library compilation loop again.
3. **Hermetic Isolation:** Dependencies live inside highly sandboxed local environments (`.ceeker/deps`), eliminating local system contamination and global version collisions.
4. **Convention over Configuration:** Focus on software architecture, not build-tool syntax loops.

## 🛠️ System Architecture

Ceeker acts as an intelligent **Orchestration Layer and Compiler Synthesis Engine**. It dynamically tracks host environmental telemetry (architectures, active shell compilers, OS boundaries) and synthesizes clean, highly optimized CMake layers in a hidden runtime sandpit.

## 📦 Declarative Manifest (`ceeker.toml`)

Instead of writing thousands of imperatively messy instructions, Ceeker projects declare intent cleanly:

```toml
[project]
name = "swaraj_core"
version = "1.0.0"
cpp_standard = 20

[dependencies]
fmt = "10.2.1"
nlohmann_json = "3.11.3"
```

## ⌨️ Command Line Interface

```bash
# Initialize a pristine new C++20 project layout
ckr init my_fortress_app

# Add an open-source library straight to your environment
ckr add dependency_name

# Parse manifests, resolve caches, and compile binaries instantly
ckr build

# Execute your synthesized binary tool directly
ckr run
```

## 🧩 Directory Architecture

Ceeker enforces a standard, logical layout to keep your working space pristine:

```text
my_fortress_app/
├── src/
│   └── main.cpp          # Application Entry Point
├── ceeker.toml           # Declarative Project Manifest
└── .ceeker/              # Git-Ignored Core Runtime Storage
    ├── CMakeLists.txt    # Autogenerated Build Pipeline
    └── build/            # Hermetic Binary Target Outputs
```

---

## 🛡️ Target Triples & ABI Protection

Ceeker manages the Application Binary Interface (ABI) matrix safely by resolving dependencies against strict platform target identifiers:

```text
[Architecture]-[Vendor]-[OperatingSystem]-[Compiler]
Example: x86_64-unknown-linux-gnu-gcc13
```

This guarantees that pre-compiled blocks are never misallocated across architectural or system call boundaries.
